# ちゃっと入退場 v1.5.1

IDだけのQRで、来場者の入退場、ブースへの参加、避難時の物資受取を記録するDelta Chat／Webxdcアプリです。管理者がブース・物資を登録し、各端末で選んだ用途を専用スキャンボタンとして保存できます。

- [chat_nyutaijo-1.5.1.xdc](chat_nyutaijo-1.5.1.xdc)：Delta Chatのスタッフ用チャットで使う最新版
- [index.html](index.html)：1ファイルで動くブラウザーデモ
- [AndroidのカメラとQR画像読取](カメラとQR画像の読取.md)：permission deniedの場合と写真・画像の読取手順
- [利用モードの画面付きガイド](chat_nyutaijo-1.5.0_layout.html)：イベント用と避難所用の切替手順
- [全機能のHTML操作マニュアル](chat_nyutaijo-1.5.0_manual.html)／[Word版](chat_nyutaijo-1.5.0_manual.docx)／[PDF版](chat_nyutaijo-1.5.0_manual.pdf)

操作マニュアルはv1.5.0の画面と操作に合わせて再作成しました。全25ページ・図23点で、利用モード切替、人物登録、QR再発行、日本語検索、イベントの入退場、避難所の外出・帰所・正式退所と世帯管理、参加・物資受取、集計・印刷、JSON引き継ぎ、CGI出力を説明しています。人物・会社・記録は架空です。詳細な項目対応は[CGI連携仕様](CGI連携仕様.md)を参照してください。

## 最初の準備

1. スタッフ用チャットへ最新版xdcを添付し、全員で**同じ添付メッセージのアプリ**を開きます。別チャットや別の添付コピーでは同じデータを共有しません。
2. 各端末の「読取端末の設定」で、表示名と担当会場を選びます。
3. 管理者は「管理者端末としてログイン」から入ります。初期パスワードは `secret` です。
4. 開場前に、人物登録、別端末での照合、入退場、参加・受取、音、印刷を試してください。

管理モードは操作画面の切替です。共有データの閲覧や変更を管理者だけに暗号的に限定する認証ではありません。パスワードとログイン状態は端末内の設定です。

## ブースと物資を登録する 管理者

1. 管理画面の「ブース・物資」を開きます。
2. 「種類」で「ブース・場所」または「物資」を選び、名称を入力します。
3. 物資では単位も入力します。例は水＝本、食料＝食、ミルク＝缶、オムツ＝枚です。
4. 「登録」を押します。「食料・水・ミルク・オムツの例を追加」からまとめて登録することもできます。
5. 不要な項目は「削除」でリストから外します。過去の参加・受取履歴は残ります。

リストは同じ添付アプリ内に共有されます。別端末では変更を受信してから反映されます。削除済みの項目に固定していたボタンは使用不可になります。同じ名前を再登録した場合は別の項目IDになるため、専用ボタンを選び直してください。

## 各端末の専用ボタンを設定する 管理者もメンバも共通

1. 「この端末の専用スキャンボタン」にある「専用ボタン設定」を開きます。
2. 管理者が登録したブース・物資から対象を選びます。
3. 物資では「1回に渡す数量」を1〜10000の整数で指定します。例えば水を2本ずつ渡すなら2です。
4. 「専用ボタンを追加・更新」を押します。設定は端末内に保存され、再起動後も使えます。
5. 「相談ブース 参加スキャン」「水 2本 受取スキャン」など、保存したボタンを押してQRを読みます。

専用ボタンは端末ごとに最大12個です。同じ対象の追加は数量の更新になります。「外す」はこの端末のボタンを外すだけで、管理者の登録リストや過去の記録は削除しません。ブースは1スキャンで1人分の参加を記録します。

カメラ・QR画像・文字列の手動入力のどれでも、開いている専用ボタンの用途と数量で記録します。登録済みの人物IDを使うので、人物情報をまだ受信していない端末では照合できません。

## 入退場と参加 受取の違い

| 操作 | 保存する内容 | 在場人数への影響 |
| --- | --- | --- |
| 入場としてスキャン | 人物、日時、会場、端末、入場 | その人物の最新状態を入場にする |
| 退場としてスキャン | 人物、日時、会場、端末、退場 | その人物の最新状態を退場にする |
| ブースの参加スキャン | 人物、日時、ブース名、会場、端末 | 変更しない |
| 物資の受取スキャン | 人物、日時、物資名、数量、単位、会場、端末 | 変更しない |

物資受取は、誰に何を何個渡したかの記録です。在庫管理、受給資格、一日一回などの配布制限、コピーQRや重複配布の自動拒否は実装していません。スキャン完了を確認してから次の人へ進んでください。

## 参加と受取を集計する 管理者

「参加・受取」タブで、期間、会場、読取端末、種類、ブース・物資、氏名・IDなどを指定します。

- 実人数は人物IDの重複を除き、記録件数とは分けて表示します。
- 数量は物資と単位ごとに合計します。水とオムツなど、異なる物資を一つの数量に足しません。
- 画面の履歴は最新200件、CSV・印刷レポートは絞り込んだ全件を対象にします。
- 「CSV」「印刷・PDF保存」「レポートHTML保存・共有」を利用できます。レポートの印刷ボタンから、OS・ブラウザーのPDF保存を選びます。
- メンバ端末には最近の参加・受取記録を表示します。

入退場の一覧・属性集計は従来の「記録一覧」「集計グラフ」です。参加・受取は入退場の人数やグラフへ混ぜません。

## 端末データを引き継ぐ JSONを推奨

### 元の端末

1. 画面上部の「データ引き継ぎ」を押します。
2. 「JSONバックアップを保存・共有」を押し、ファイルを保存します。
3. ファイルを新しい端末へ渡します。個人情報を含む平文JSONなので、保存先と共有先を確認してください。

JSONには人物、入退場、参加・受取、ブース・物資・会場の登録履歴、未送信記録、端末名・会場・スキャン音・専用ボタン設定を含みます。リセット前の保存履歴も含みます。管理パスワードとログイン状態は含みません。

### 新しい端末

1. 使用する最新版アプリで「データ引き継ぎ」を開き、JSONファイルを選択します。
2. 元端末・保存日時・件数を確認します。件数はリセット前も含む保存履歴全体です。
3. 「端末名・会場・音・専用ボタンの設定も引き継ぐ」を必要に応じて選びます。
4. 通常は「端末交換として元端末IDも引き継ぐ」をOFFにします。新しい端末IDで記録を開始し、過去の履歴の端末IDは保持します。
5. 故障端末などの後継として同じ端末IDを使う場合だけONにし、元の端末での利用を終了してください。
6. 「選択内容を取り込む」を押します。既存データへIDで統合し、追加された履歴イベントを同じ添付アプリへ順次共有します。

同じJSONファイルを再度取り込んでも同じイベントIDの記録は増えません。異なる内容が同じIDを使っている場合や破損ファイルは取り込みません。端末の保存容量が不足すると取込を中止します。上限はファイル50MB・履歴イベント10万件ですが、実際には端末保存領域の空き容量によります。

別イベントや別会場運用のバックアップを不用意に混ぜないでください。記録のリセット履歴も統合されます。引き継ぎ後は人数・人物・リスト・専用ボタンを確認し、元端末のデータは確認が済むまで残してください。

## v1.0.8以前からの引き継ぎ

旧版にはJSON保存がないため、旧版の「記録一覧」で日付を空欄にし、必要な範囲をCSV出力します。新版の「データ引き継ぎ」でその入退場CSVを選ぶと、人物と入退場履歴を取り込めます。

CSVでは専用ボタン・設定やブース・物資リストは復元できません。元のCSVに人物ID・端末IDがあれば保持し、人物IDがない場合は新しいIDを作るためQRの再発行が必要です。参加・受取CSVは引き継ぎ用ではなく、参照・集計用です。参加・受取を引き継ぐにはJSONを使ってください。

同じCSVの再取込では同じ記録を増やしません。ただし、同じ履歴をCSVとJSONの両方で重ねて取り込む運用は避けてください。CSVには元の履歴イベントIDがなく、形式が違うデータ間での重複を保証して除去できません。

## 既存機能の要点

- 来場者IDのQRだけを配布する運用なので、来場者本人のDelta Chat導入は不要です。
- 氏名は必須、年齢は0〜120歳、性別や連絡先などは任意です。登録済み人物の再選択で同じIDのQRを再表示できます。
- 読取端末ID・その時点の端末名を記録し、同じアカウントの複数端末も端末内IDで区別します。端末IDはハードウェア固有番号や認証情報ではありません。
- 「スキャン音：ON/OFF」は端末ごとに保存し、有効な記録の成功時だけ短い音が鳴ります。
- 入退場の属性集計は業種・会社・部署・役職・年代・性別・会場・読取端末に対応し、期間・会場・端末で絞り込めます。
- 時間帯別・月別・曜日別にも同じ条件を適用します。年をまたぐ期間の月別は同じ月を合算します。

## 通信とデータの扱い

- ブラウザーデモは端末内に保存し、Delta Chat端末へ通知しません。ファイルの場所やブラウザーによって保存領域が異なる場合があります。
- Delta Chatでも、同じWi-Fiへ接続するだけでは共有を保証しません。未同期の人物・リスト・履歴は他端末にまだ反映されていません。
- 「共有待ち0件」はホストへの引渡しであり、相手端末の受領確認ではありません。アプリを閉じると再送処理はホストの対応に依存します。
- 登録情報と履歴は同じ添付アプリの参加者へ共有されます。管理者だけへの秘密配送ではありません。
- 「すべての記録を削除」は入退場と参加・受取の表示対象をリセットし、人物・リストや過去の通信データを物理消去しません。
- 同じ端末IDを複数の現役端末へコピーしないでください。追加端末への取込では元端末IDの引き継ぎをOFFにします。

## v1.3.0 備考とCGI避難者データ出力

来場者登録に自由記入の「備考」（最大2,000文字）を追加しました。再編集、検索、通常CSV、JSON引き継ぎにも対応します。QRには個人情報や備考を入れず、人物IDだけを保持します。

管理者の「CGI出力」で、来場者を避難者として出力できます。esbbs.cgi向けHXL CSVと、sbbs.cgi・esbbs.cgi共通のMIMEメールTXTをまとめたZIPを選べます。登録人物すべて／現在在場中／入退場記録ありで絞り込めます。操作手順と項目対応は[CGI連携仕様](CGI連携仕様.md)に記載しています。


## ブース参加・物資受取履歴の備考出力

CGI向けのHXL CSVとメールTXT ZIPの両方で、人物ごとの全ブース参加・物資受取履歴を備考に含めます。日時の古い順に、参加／受取の種類、登録時のブース名・物資名、受取数量と単位、会場、読取端末名とIDを記載します。削除済みブース・物資も残っている履歴を出力します。履歴がない人物は履歴を追加しません。他の人物の履歴は含めません。

「CGI出力」の条件は出力する人物の絞り込みです。その人物の履歴は、参加・受取画面の期間や種類の絞り込みにかかわらず全件を含めます。履歴は備考の原文を変更せず出力時に追加するため、出力を繰り返しても登録済み備考は増えません。


## v1.3.0 避難所の状態と世帯管理

入場を入所として使い、一時外出・帰所・正式退所を専用ボタンで記録できます。在所中と一時外出中を分け、その合計を受入継続人数として表示します。正式退所済みの人数は別表示です。

一時外出は在所中、帰所は一時外出中の人物に記録します。正式退所は在所中・外出中・従来退場の人物に記録できます。正式退所後は「入場」で再入所できます。従来の退場は外出か正式退所か判別できないため、区分未確認として扱います。CGIの退所日時は最新記録が正式退所のときだけ出力します。帰所では受付日時を更新せず、入場・再入所では更新します。

人物登録の「新しい世帯IDを作成」で世帯IDを作り、世帯名と関係を記入してQR生成で保存します。家族には既存世帯を選んで別の人物ID・QRを発行します。管理者の「避難者・世帯」では人物の追加・編集、世帯別の在所状態、世帯・状態CSV、印刷・PDF保存を利用できます。所属解除は人物の世帯欄で「世帯に所属しない」を選んで保存します。世帯名は各人物の登録値で、改称は所属者ごとに変更します。

世帯単位の一括スキャン・一括配布制限はありません。各人のQRを読み取り、記録と点呼を照合してください。世帯情報と新しい行動区分はJSONおよび入退場CSVで引き継げます。CGIへは世帯情報も備考に含めます。世帯・状態CSVは一覧用で、移行にはJSONを使います。

入場回数には帰所、退場回数には一時外出と正式退所を含みます。移動に関する記録件数の集計です。世帯の現在状態とは区別してください。

### 旧版からの更新

元のアプリでJSONバックアップを保存してから、最新版で取り込みます。全担当端末で同じ新しい添付アプリを使用してください。旧版は一時外出・帰所・正式退所の区分を理解できず、旧版との混在運用には対応しません。


## v1.3.1 入力案内と自動入力の改善

- 本人の「氏名」と「世帯名」が別の入力項目であることを明記しました。
- 氏名が未入力のままQR生成を押すと、理由を表示し、本人の氏名欄へ移動します。世帯名だけでは人物を登録しません。
- 世帯IDの作成・世帯の選択・QR生成の際に画面の入力値を読み直し、ブラウザーの自動入力などで入力イベントが発生しない場合でも氏名などを保持します。

v1.3.0から移行する場合も、元のアプリでJSONバックアップを保存し、新しい添付アプリで取り込んでください。全担当端末で同じv1.5.1の添付アプリを使用します。


## QRの再発行 v1.4.0

紛失・破損・再印刷が必要な場合、同じ人物IDのQRを再発行できます。メンバ端末と管理者端末のどちらでも使えます。

1. QR発行画面の「QRの再発行（紛失・再印刷）」を開きます。
2. 氏名、人物ID、世帯名、世帯ID、会社、電話番号、メールアドレスのいずれかで検索します。
3. 検索結果の氏名・人物ID・世帯名などで本人を確認し、「同じIDでQRを再発行」を押します。同姓同名の場合はIDなどを照合してください。
4. 再表示されたQRを「QR画像を保存・共有」または「印刷」で本人に渡します。

下の登録人物欄で人物を選び、検索を空欄にすると、その人物専用の再発行ボタンからも操作できます。管理者の「避難者・世帯」にも、各人の「QR再発行」ボタンがあります。

再発行は保存済みの人物情報を使い、人物IDを新しく作りません。入退所、ブース参加、物資受取、世帯の紐づけと履歴を保ちます。新しい入退所・受取記録や人物登録を追加する処理ではありません。編集中の未保存の変更は保存せず、登録済みの情報に戻してQRを表示します。

同じQRの再表示・再印刷なので、紛失した旧QRは無効になりません。旧QRの失効や新しい人物IDへの履歴移動は行いません。別端末で検索結果が出ない場合は、同じ添付アプリの人物情報が同期されているか確認してください。端末を交換した場合はJSONバックアップを復元してから再発行します。


## v1.4.1 日本語入力と全角検索の修正

QR再発行の検索欄を、入力のたびに作り直さないようにしました。IME変換中は検索と画面再描画を待ち、変換確定後に検索結果を更新します。同期受信による画面更新も変換確定まで待ちます。検索文字の途中への挿入・削除でもカーソルを維持します。

再発行検索は全角・半角英数字の違いを吸収します。入力した文字や人物の登録情報は書き換えません。日本語への変換は端末のIMEで通常どおり行ってください。

ChromeのIME操作を使った自動試験で「やまだ→山田」、全角英数字検索、変換中の別端末更新、カーソル途中の編集をメンバ・管理者両画面で確認しました。実機の各OS・各日本語IMEでの操作は未検証です。


## v1.5.0 イベント用と避難所用のレイアウト切替

画面上部の「利用モード」で、この端末の用途を選択します。

| 用途 | スキャンボタン |
|---|---|
| イベント用 | 入場・退場 |
| 避難所用 | 入所・帰所、一時外出、正式退所 |

避難所用では一時外出と正式退所を説明付きの別枠で表示し、従来の退場ボタンは隠します。手動貼り付けの区分も用途に合わせて切り替わります。初期表示はイベント用です。各端末で用途を選んでください。メンバ・管理者の両方で使用できます。

表示用途は端末内に保存し、設定を含むJSON引き継ぎにも対応します。モードのない旧版JSONや入退場CSV、設定を引き継がない場合は、移行先端末の用途を維持します。切替時はスキャン操作と今回の記録区分をリセットし、人物情報の入力は保持します。過去の記録を変換したり削除したりしません。

## v1.5.1 QR画像読取とカメラの改善

画像をFileReaderで読み込む方式に変更し、blob URLが利用できない環境でも解析できるようにしました。透過画像を白背景に合成し、白黒反転、画像縮尺の変更、大きな画像の領域別解析に対応します。画像が不鮮明な場合など、すべてのQRの読取を保証するものではありません。

「保存済みのQR画像を選んで読む」「カメラで写真を撮って読む（対応端末）」を分け、読取経過とエラーを消えない説明欄に表示します。同じファイルの再選択にも対応します。未登録・未同期のQRは「QR読取済み・記録なし」と表示し、画像の読取失敗と区別します。

カメラ拒否時は理由と権限の確認方法を表示し、「カメラを再試行」も利用できます。アプリからAndroidやDelta Chatの権限制限を解除することはできません。撮影用ファイル選択が使えるかどうかも端末・Delta Chatの対応に依存します。[詳しい手順](カメラとQR画像の読取.md)を参照してください。

操作マニュアル3形式はv1.5.0版を基本操作に使い、変更されたスキャナ画面と対応手順は上の説明を参照してください。
